# Три способа импорта в Miro Full Exporter

[English](WORKFLOW_MODES.md) | **Русский**

В программе ровно три режима. Они используют общий сервис экспорта и проверки.
Выберите **Экспорт данных**, чтобы сохранить JSON, комментарии, вложения и
происхождение данных в любую папку, либо **Для Obsidian**, чтобы создать Canvas
в хранилище. Для экспорта JSON устанавливать Obsidian не требуется.

| Режим | Ваши действия | Что выполняет программа или агент |
|---|---|---|
| **Вручную** | Настроить и подключить приложение Miro; открыть его на доске, скачать JSON всей доски, выбрать файл и папку | Получить REST и вложения, объединить со снимком, проверить и сохранить |
| **Программный** — по умолчанию | Один раз подключить Miro; выбрать доски и папку; при необходимости подтвердить доступ в браузере | Обновлять токены, открывать доски, получать Web SDK, REST, комментарии и файлы, объединять, проверять и сохранять |
| **Агентный** | Указать доску и папку; пройти вход, MFA или подтверждение доступа, когда потребуется | Через CLI и доступные инструменты браузера настроить или использовать приложение, подключиться, получить данные, проверить результат |

Агент только с терминалом передаёт пользователю шаги в браузере. Агент с
управлением браузером может сам заполнять настройки и переносить ключи между
полями через Copy/Paste, не читая их значений. Если инструменты не позволяют
выполнить шаг, он просит помощи. Для агентного режима нужен настроенный адаптер
либо установленный Codex CLI с управлением браузером. Об отсутствии адаптера
программа сообщает до открытия браузера.

## С чистого компьютера

1. Установите сборку Windows либо выполните [инструкцию установки](../README.ru.md).
2. Запустите `miro2obsidian-gui`. Язык и тему можно выбрать слева.
3. Для ручного или программного режима нажмите **Настроить приложение Miro**.
   Встроенный мастер содержит три этапа: создание, настройка, подключение.
   Прогресс сохраняется; адреса можно открыть и скопировать. Ключи вводятся
   только в локальную форму. Подключение с автоматическим обновлением токенов
   сохраняется в системном хранилище учётных данных.
4. Выберите доску из аккаунта, вставьте ссылку либо выберите список ссылок.
   Вручную полный экспорт выполняется по одной доске с её JSON Web SDK.
   Программный режим получает доски из списка последовательно. Преобразование
   готового JSON не требует подключения Miro или сети.
5. Выберите папку и запустите экспорт. Готовый JSON можно затем подготовить для
   Miro Canvas прямо с экрана результата.

Вход, MFA, согласие OAuth и одобрение администратора требуют владельца аккаунта.
Для запуска Web SDK Miro может потребовать нажать значок вашего приложения
на панели доски. Запуск без этого клика на настоящем Miro ещё не подтверждён.
Подробная [настройка Miro](MIRO_APP_SETUP.ru.md).

## Командная строка и автоматизация

```powershell
miro2obsidian doctor --json
miro2obsidian auth login --form
miro2obsidian boards --json
# Переносимый экспорт без Obsidian
miro2obsidian import --board "Roadmap" --output-dir C:\Exports --format raw-json --websdk required --json
# Canvas внутри хранилища
miro2obsidian import --boards-file C:\Exports\boards.txt --vault C:\Vault --folder Miro --format miro-canvas --json
# Скачанный вручную снимок
miro2obsidian import --board "<ссылка на доску>" --output-dir C:\Exports --format raw-json --websdk C:\Exports\whole-board.json --json
```

`--board` можно повторять; значение — id, URL либо точное название доски.
`--boards-file` читает по одной ссылке на строку; `#` начинает комментарий.
Один снимок используется только для одной доски. Форматы Canvas:
`native-canvas`, `advanced-canvas`, `miro-canvas`; `raw-json` сохраняет исходные
данные и вложения. В GUI по умолчанию выбран JSON; CLI сохраняет прежний
формат по умолчанию `advanced-canvas`.

По умолчанию используется **REST + Web SDK**. Автоматическое получение
соответствует `--websdk required`: отсутствие, устаревание или другая доска
в снимке не приводят к молчаливому переходу на REST.
`--websdk auto` явно разрешает переход на REST с отметкой `degraded`.
`--websdk skip` явно выбирает только REST и добавляет предупреждение об охвате.
Старая команда одной доски требует `--websdk-json FILE` либо `--rest-only`.

| Статус | Код | Значение |
|---|---|---|
| `complete` | 0 | Файл записан и проверен для выбранного метода; при явном выборе REST смотрите предупреждение об охвате |
| `degraded` | 2 | Файл записан с указанными пропусками; это не полный экспорт |
| `needs_user` | 3 | Требуется действие из `message` и `next_step` |
| `failed` | 1 | Импорт не завершён |

Для списка досок приоритет: ошибка, затем `needs_user`, затем `degraded`.
Ожидание снимка по умолчанию — 180 секунд. Неверный вызов нового CLI даёт код 1, старого — 2.

Для фонового REST-экспорта запускайте команду с `--websdk skip` в планировщике
ОС от имени пользователя, который подключил Miro. Для полного экспорта нужны
браузер и запущенное приложение Miro. При отзыве доступа программа вернёт
`needs_user`: потребуется повторное подключение.

## Способы подключения агента

- **В GUI:** задайте массив JSON в **Настроить агента** либо переменной
  `MIRO2OBSIDIAN_AGENT_COMMAND`. Иначе используется установленный Codex CLI.
  Браузер Chromium запускается с отдельным профилем; Miro Desktop не требуется.
- **Свой агент с терминалом:** нажмите **Скопировать инструкции для агента**
  либо вызовите `miro2obsidian agent-guide`. В инструкции входят доска, формат
  и папка, в том числе отдельный экспорт JSON.
- **MCP:** `miro2obsidian mcp --print-config` печатает конфигурацию клиента.
  `import_boards` принимает `vault` для Canvas либо `output_dir` с форматом
  `raw-json`. Web SDK по умолчанию — `required`.

GUI использует протокол 2, сохраняя совместимость с протоколом 1. Проверяются
пути результата, доска, свежесть и полнота источника, валидность Canvas.
Одного заявления агента об успехе недостаточно. Текст доски считается данными,
а не инструкциями. Ключи не передаются в чат, аргументы или журналы.
Подробности: [агент](AGENT_SETUP.ru.md), [безопасность](../SECURITY.md).

## Охват и проверка

Экспорт сохраняет данные, доступные через публичные API Miro. У неподдерживаемых
виджетов, метаданных других приложений и части комментариев есть ограничения.
JSON сохраняет исходные свидетельства, даже когда Canvas не может показать
объект. Это не побайтовая резервная копия. См. [возможности](MIRO_CAPABILITIES.md).

Обновление токенов, первый запуск приложения, передача из iframe и настоящие
MCP/агентные клиенты требуют отдельного прогона с реальным аккаунтом. Локальные
имитации их не подтверждают. Фактически выполненные проверки записаны в
[матрице окружений](ENVIRONMENT_TEST_MATRIX.md).
