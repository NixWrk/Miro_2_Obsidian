# Подключение собственных досок Miro

[English](MIRO_APP_SETUP.md) | **Русский**

Здесь описано, зачем Miro to Obsidian требуется собственное Miro Developer App,
как его создать и какие части настройки пока выполняются вручную.

## Короткий ответ

- Программировать ничего не нужно.
- Если вы можете устанавливать приложения в team целевой доски, настройка обычно
  занимает 10-20 минут.
- Если требуется согласование администратора team, понадобится больше времени.
- Приложение настраивается один раз, после чего может экспортировать все доски,
  доступные одновременно авторизованному пользователю и установленному app.
- Программа сама запускает локальные серверы и сама получает захват Web SDK.
  Файлами JSON вам заниматься не нужно, если только автоматическая передача не
  сработала.
- Несколько шагов остаются за вами, потому что модель безопасности Miro отдаёт
  их человеку: создать приложение, войти, одобрить доступ и, возможно, один раз
  нажать на значок приложения. См. [Режимы работы](WORKFLOW_MODES.ru.md).

Собственное app требуется моделью безопасности Miro. Репозиторий не должен
поставлять один общий client secret, который смешивает доступ разных
пользователей к их доскам.

## Какой выигрыш это даёт

| Без собственного Miro app | С собственным Miro app |
|---|---|
| Только конвертация уже имеющегося JSON | Прямая авторизация в вашем Miro account |
| Нет автоматического списка досок | Список досок, видимых пользователю и app |
| Нет свежего REST-экспорта | REST items, comments и обязательные assets |
| Нет Web SDK capture | Максимальный payload, доступный внутри открытой доски |
| Нет воспроизводимой проверки источника | Проверка доски, свежести, полноты и provenance |

Комбинация REST и Web SDK даёт максимум данных, который открывают публичные API
Miro. Она не может восстановить скрытые внутренние данные, которые Miro не
выдаёт ни через один публичный интерфейс.

## Что потребуется

- Miro account с доступом к целевой доске;
- право устанавливать app в team этой доски или помощь администратора team;
- программа: готовая сборка либо этот репозиторий и Python 3.13;
- Obsidian vault для итогового Canvas.

Miro Developer team подходит для безопасных тестов, но app, установленное только
в ней, не появится на доске другой team. То же app нужно установить именно в
team реальной доски.

## 1. Создайте Miro app

1. Войдите в Miro.
2. Откройте avatar, затем **Developer Hub** → **Your apps** либо сразу
   [Miro Developer Hub](https://developers.miro.com/page/developer-hub#your-apps).
3. Выберите организацию и существующую Developer team. Если её нет, создайте
   новую и примите developer terms.
4. Создайте app в этой team.
5. Задайте понятное имя, например `Miro to Obsidian - local export`.

Это действие не переносит и не копирует доски. Оно создаёт credentials и
границу разрешений для локального экспорта.

## 2. Настройте URL

Быстрее всего через манифест. Выполните `miro2obsidian setup manifest` (в мастере
GUI есть действие **Copy manifest**) и, если на странице настроек приложения
можно редактировать манифест, вставьте его туда и сохраните. Он задаёт имя
приложения, два URL ниже и два scope. Если редактора манифеста нет, введите те
же значения вручную. Предлагает ли такой редактор страница Miro, вживую пока не
проверено.

`miro2obsidian setup guide` печатает весь этот чек-лист в терминале, а
`miro2obsidian setup open` открывает Developer Hub.

Введите в настройках app точные значения:

| Настройка Miro | Значение |
|---|---|
| App URL / SDK URI | `http://localhost:8766/index.html` |
| OAuth redirect URI | `http://localhost:8765/callback` |

Если у callback URI есть options, включите **Use this URI for SDK
authorization**. Сохраните настройки.

`localhost` означает, что приложение обслуживается только вашим компьютером.
Miro разрешает HTTP для локальной разработки на `localhost`; удалённый сервер
потребовал бы HTTPS.

Host является частью redirect URI. Не заменяйте `localhost` на `127.0.0.1`, если
второй URI отдельно не зарегистрирован в Miro и не настроен локально.

## 3. Выберите разрешения

Для обычного экспорта нужен минимальный набор:

| Scope | Для чего нужен |
|---|---|
| `boards:read` | Чтение items и метаданных доски |
| `team:read` | Список видимых teams и досок |
| `boards:write` | Необязательные developer probes, создающие тестовые items |

Обычному пользователю достаточно `boards:read` и `team:read`.
`boards:write` добавляйте только для явно выбранного probe, который создаёт
элементы. Для полноты read-only экспорта этот scope ничего не добавляет.

## 4. Установите app в правильную team

1. В настройках app нажмите **Install app and get OAuth token**.
2. Выберите team, которой принадлежит целевая доска.
3. Проверьте scopes и нажмите **Install & authorize**.
4. Если нужной team нет или установка запрещена, попросите её администратора
   одобрить app.

Выбор team критичен. App из Developer team не появляется автоматически на
досках личной, корпоративной или клиентской team.

## 5. Подключите программу к своему приложению

Скопируйте **Client ID** и **Client secret** из настроек app. Не отправляйте их в
issue, чат, скриншот или файл под git. Затем подключитесь одним из двух способов:

- **Окно программы.** Запустите `miro2obsidian-gui` и откройте мастер **Set up
  Miro app**. Он показывает по одному шагу с кнопками Copy и Open. Введите оба
  значения и одобрите доступ в браузере.
- **Командная строка.** Выполните `miro2obsidian auth login --form`. В браузере
  на вашем компьютере откроется форма. Вставьте в неё Client ID и Client secret и
  одобрите доступ в Miro. Команда никогда не принимает секрет аргументом. Без
  `--form` она берёт `MIRO_CLIENT_ID` и `MIRO_CLIENT_SECRET` из окружения либо
  спрашивает их в скрытом приглашении.

Программа сохраняет одно подключение в системном хранилище учётных данных
(Windows Credential Manager, macOS Keychain или Linux Secret Service). В нём
лежат Client ID, **Client secret**, access и refresh token, срок действия и
team. Секрет хранится, чтобы программа могла обновлять токен без вас. Об этом
компромиссе и о том, как всё удалить, см. [SECURITY.md](../SECURITY.md).

Токены обновляются сами, поэтому при создании app можно включить **Expire user
authorization token**. Раньше эту опцию требовалось оставлять выключенной. Если
вы её уже включили, ничего менять не нужно.

Если нужной доски потом не видно, установите app в team, которой она
принадлежит, и подключитесь заново, выбрав эту team в окне OAuth. Чтобы забыть
подключение, выполните `miro2obsidian auth logout` (в GUI есть такая же кнопка).
Программа по возможности просит Miro отозвать токен и в любом случае удаляет
сохранённое подключение с вашего компьютера.

Если системного хранилища нет, задайте `MIRO_ACCESS_TOKEN` в окружении на время
запуска. Такой токен сам не обновляется.

## 6. Проверьте подключение

```powershell
miro2obsidian auth status --verify
miro2obsidian boards
miro2obsidian doctor
```

`auth status --verify` спрашивает Miro, работает ли токен. `boards` показывает
доски, видимые и вам, и app (`--query` фильтрует по названию). `doctor`
проверяет хранилище, порты `8765` и `8766` и браузер. Если ожидаемой доски нет,
см. таблицу ниже.

Теперь можно выполнить строгий REST-путь: board items, REST-комментарии и
обязательные скачиваемые вложения:

```powershell
miro2obsidian import --board "<название, URL или id доски>" --vault <vault> --websdk skip
```

## 7. Максимально полный экспорт, автоматически

Оставьте Web SDK в автоматическом режиме (`--websdk auto`, по умолчанию). Для
каждой доски программа:

1. запускает локальный сервер на порту `8766` (он указан в вашем App URL);
2. просит приложение Miro сделать захват этой доски;
3. открывает доску в браузере по умолчанию;
4. принимает захват всей доски через loopback, проверяет его и сразу запускает
   REST-экспорт.

Если Miro сам запускает приложение при открытии доски, клик не нужен. Если
примерно через 20 секунд ничего не произошло, нажмите на значок приложения на
левой панели доски (**+ More apps**, затем `Miro to Obsidian - local export`).
Программа ждёт до 3 минут на доску (`--capture-timeout`).

Если захват не пришёл, `--websdk auto` всё равно запишет Canvas только из REST,
пометит доску как `degraded` и скажет, чего может не хватать. Если вместо этого
нужна просьба о клике, используйте `--websdk required`.

Запускает ли Miro приложение при открытии доски без клика, вживую пока не
проверено. Рассчитывайте на один клик.

### Запасной путь: скачать захват вручную

Если автоматическая передача не работает, запустите экспортёр сами:

1. Запустите `miro2obsidian websdk-serve --port 8766`.
2. Откройте доску, откройте приложение и нажмите **Export board**, а не
   **Export selection**. Пока сервер работает, захват уходит в программу сам.
   Кнопки **Download JSON** и **Copy JSON** остаются.
3. Передайте скачанный файл через `--websdk <файл>` (CLI) или **From file** (GUI).
   Он должен относиться к той же доске и быть свежим. Чужой или устаревший захват
   отклоняется.

Передача описана в [README экспортёра](../tools/miro_websdk_exporter/README.md#handoff-to-the-local-program).

## Частые проблемы

| Симптом | Вероятная причина | Что сделать |
|---|---|---|
| `ERR_CONNECTION_REFUSED` в Miro | Local server не запущен на нужном порту | Запустите импорт или `miro2obsidian websdk-serve --port 8766` и не закрывайте его |
| `404 File not found` | App URL ведёт на старый путь или другой static server | Указать `http://localhost:8766/index.html` |
| App отсутствует на доске | Оно установлено в другую team | Установить в team этой доски |
| OAuth callback не работает | Отличается host, port или path | Везде использовать `http://localhost:8765/callback` |
| Список досок пуст или неполон | Нет доступа пользователя, установки в team или `team:read` | Проверить все три условия; при необходимости обратиться к admin |
| Порт `8765` занят | Web SDK compatibility server конфликтует с OAuth callback | Web SDK держать на `8766`, OAuth на `8765` |
| Приложения нет на панели доски | Оно установлено в другую team | Установите его в team этой доски (шаг 4) и заново откройте доску |
| Тайм-аут захвата (`websdk_capture_timeout` либо доска `degraded` с `websdk_unavailable`) | Miro не запустил приложение сам | Нажмите на значок приложения на открытой доске и повторите ту же команду. Чтобы вместо понижения результата получить просьбу о клике, используйте `--websdk required` |
| Порт `8766` занят | Его держит другая программа или старый сервер другого вида | Остановите её и запустите снова. Работающий `miro2obsidian websdk-serve` используется повторно сам. `doctor` покажет, кто занимает порт |
| Захват отклонён | Он относится к другой доске или устарел | Откройте нужную доску и сделайте захват заново. Не используйте старый файл |
| Miro сообщает, что токен отозван или истёк | Доступ отозван или app удалено | Снова выполните `miro2obsidian auth login --form` |
| `WinError 5` при записи Canvas | Открытый Obsidian удерживает создаваемый файл | Закройте Obsidian, повторите экспорт и откройте готовый Canvas после успешного завершения |
| Probe сообщает о permission | App настроено read-only | Добавить `boards:write` только для намеренного probe |

## Удобство для начинающих: что сделано и что планируется

Целевой сценарий: скачать программу, запустить один мастер, выбрать доску и
Obsidian vault, нажать **Export**. Начинающему не должны требоваться terminal,
Python, Node.js, переменные окружения, пути к JSON и знания о локальных портах.

Уже есть:

- Пошаговый мастер **Set up Miro app** в окне программы с кнопками Copy и Open и
  тот же чек-лист в командной строке (`setup guide`).
- Манифест для вставки (`setup manifest`).
- Учётные данные в системном хранилище с автоматическим обновлением токена и
  явным отключением (`auth logout`).
- Локальные службы OAuth и Web SDK запускаются и останавливаются сами во время
  импорта. Конфликты портов показывает `doctor`.
- Прямая передача захвата Web SDK в программу с одноразовым токеном процесса.

Ещё планируется или не проверено:

1. Подписанный установщик Windows или portable-пакет со своим runtime.
2. Продолжение с последнего завершённого шага после закрытия Miro или браузера.
3. Поиск Obsidian vault и настроек вложений и выбор безопасных значений.
4. Единый ход выполнения от выбора доски через REST, комментарии, вложения,
   объединение с Web SDK, конвертацию и проверку до готового Canvas.
5. Живое подтверждение, что приложение запускается при открытии доски без клика.
6. Проверка всего пути на чистом Windows-компьютере с новыми пользователями.

Для создания app по-прежнему нужен аккаунт с правом создавать и устанавливать
app и явное согласие на запрошенные права. Одобрение администратора team остаётся
внешним условием там, где установка ограничена.

## Требования к дизайну интерфейсов

### Панель в Miro

- Одна ясная primary action для обычного экспорта всей доски.
- Отображение текущей доски, connection state, версии exporter и полноты.
- Generated probes и diagnostics только в явном advanced mode.
- Progress, success и исправимые ошибки прямо внутри панели.
- Поддержка light/dark appearance Miro, keyboard navigation, заметного focus и
  корректного toolbar icon.
- Основной путь - безопасная прямая передача локальному companion; JSON download
  остаётся advanced fallback.

### Локальное desktop-приложение

- Вместо плотной формы - пошаговый первый запуск и понятный export flow.
- Beginner defaults отдельно от advanced source/converter controls.
- Board picker и vault picker вместо ручного ввода ID и путей.
- Одна status-зона с progress, следующим действием, retry и logs по запросу.
- Ошибки на языке пользователя с точным repair action.
- Keyboard accessibility, scaling, light/dark themes и читаемая компоновка на
  типичных Windows-экранах.

## Критерий beginner-ready

Релиз готов для начинающих, когда человек на чистом Windows-компьютере может:

1. скачать и запустить программу без developer tools;
2. создать и подключить Miro app, следуя только встроенному мастеру;
3. понимать каждое ручное permission-действие до его подтверждения;
4. выбрать видимую Miro board и Obsidian vault без копирования ID и paths;
5. получить maximum export без ручной работы с JSON и local servers;
6. восстановиться после закрытого browser, неверной team, scope или занятого port;
7. найти готовый Canvas и понятный отчёт о полноте.
